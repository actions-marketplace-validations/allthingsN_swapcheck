How it works

From an announcement to a pull request

One line, five stops. Only test spends money, and it shows you the maximum first.

find

Many models in. Five out. One tested.

The registry can tell you what exists. Only your cases can tell you what works for you, so the shortlist is where the listing stops and the testing starts.

test

A difference has to survive the maths, then happen again

The same prompt gives different answers from one run to the next, so one run of each model proves nothing.

  1. Run each case several times on both models.
  2. Test each case with Fisher's exact test, then correct across the suite with Benjamini-Hochberg.
  3. Re-run anything flagged on a fresh sample. A drop that does not repeat does not count.
Verdicts

Four verdicts. None of them is "safe".

Swapcheck only knows what your cases cover. A clean result means nothing moved on those cases, at that sample size, on that day.

Nothing differed beyond noise on your cases. It is not a guarantee about anything your cases do not test.exit 0
Check results, tool calls or token use moved beyond noise, with no confirmed drop in pass rate. Read the report and decide.exit 0
At least one case dropped, and dropped again on a fresh sample. CI fails.exit 1
Over 20% of calls failed, the budget ran out, or there were fewer than six usable cases. It will not guess.exit 3

Security posture

It runs on your machine, with your keys

There is no Swapcheck server to send anything to. The only network calls are the registry fetch, your model providers, and the GitHub API when you ask for a PR.
